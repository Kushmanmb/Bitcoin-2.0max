Why Bitcoin 2.0max?

A high-performance Bitcoin fork engineered for throughput, independence, and scalability.

⚡

10× Faster Confirmations

60-second target block time means transactions confirm in under a minute, versus Bitcoin's 10-minute average — ideal for high-frequency use cases.

📦

32× Larger Blocks

32 MiB maximum block size accommodates far more transactions per block, dramatically increasing throughput without sacrificing decentralisation.

🔌

Independent Wallet Relay

Wallet functionality is delegated to any standard Electrum server (Electrum Personal Server, Fulcrum, Electrs). No external infrastructure dependencies.

🔒

OpenSSL Cryptography

Full elliptic-curve cryptography using OpenSSL, with a clean C++17 API for signature generation, verification, and key management.

🐳

Docker-Ready

Multi-stage Dockerfile ships a stripped, minimal runtime image. Pre-built images published to GitHub Container Registry on every tagged release.

🧪

Fully Tested CI/CD

Comprehensive unit tests for consensus parameters, config loading, cryptographic operations, transactions, and P2P handshake — validated on every commit.

Get Started

Build and run your own Bitcoin 2.0max node in minutes.

1

Prerequisites

Ensure the following are installed on your system:

cmake >= 3.16
g++ / clang++ with C++17 support
libssl-dev  (OpenSSL development headers)

On Debian/Ubuntu: sudo apt install cmake g++ libssl-dev

2

Clone & Build

git clone https://github.com/Kushmanmb/Bitcoin-2.0max.git
cd Bitcoin-2.0max

cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)

The resulting binary is build/bitcoin2maxd.

3

Configure

mkdir -p ~/.bitcoin2max
cp conf/bitcoin2max.conf ~/.bitcoin2max/bitcoin2max.conf
# Edit settings as needed — key options:
#   targetblocktime=60      # 60-second blocks
#   maxblocksize=33554432   # 32 MiB
#   electrumhost=127.0.0.1
#   electrumport=9050
4

Run Your Node

# Start with default config
./build/bitcoin2maxd

# Or specify a custom config
./build/bitcoin2maxd --conf /path/to/bitcoin2max.conf

# Print help
./build/bitcoin2maxd --help

Build Options

Option Default Description
BUILD_TESTS ON Build unit tests (fetches Catch2 automatically)
ENABLE_ELECTRUM ON Compile in the Electrum JSON-RPC client
ENABLE_TOR OFF Route Electrum traffic over a Tor SOCKS5 proxy 
# Example: build without tests
cmake -B build -DBUILD_TESTS=OFF
cmake --build build

Docker

Run Bitcoin 2.0max in an isolated, production-ready container.

Build Locally

docker build -t bitcoin2maxd .

docker run -d \
  -v ~/.bitcoin2max:/var/lib/bitcoin2max \
  -p 8333:8333 \
  bitcoin2maxd

Pull Pre-built Image

docker pull \
  ghcr.io/kushmanmb/bitcoin-2.0max:latest

docker run -d \
  -v ~/.bitcoin2max:/var/lib/bitcoin2max \
  -p 8333:8333 \
  ghcr.io/kushmanmb/bitcoin-2.0max:latest

Exposed Ports

8333 P2P Network
8332 JSON-RPC
9050 Electrum

Roadmap

The path to a fully featured, high-throughput Bitcoin node.

v2.0.0 ✅

Foundation

  • CMake-based build system (C++17)
  • Configurable block parameters (60 s target, 32 MiB blocks)
  • Electrum JSON-RPC client
  • Config file parser
  • Basic P2P node loop
  • Unit tests & CI/CD
  • Docker image
v2.1.0

Network Layer

  • Full peer handshake protocol
  • Persistent peer address book
  • Async I/O via Boost.Asio
  • Tor SOCKS5 integration
  • DNS seed bootstrap
v2.2.0

Block Validation

  • Script interpreter (OP codes)
  • Merkle tree verification
  • Chain-tip selection
  • Reorg logic
v2.3.0

Mempool & Relay

  • In-memory transaction pool
  • RBF (Replace-By-Fee)
  • Fee estimation API
v2.4.0

Wallet API

  • Electrum server-side protocol
  • Address-to-UTXO index
  • Balance query
  • SSL/TLS for remote connections
v3.0.0

Performance & Scalability

  • LevelDB / RocksDB UTXO set
  • Parallel script validation
  • SIMD-accelerated SHA-256
  • Profile-guided optimisation (PGO)
